# Ordered model script and factor service

The generic service-5 adapter connects the actual model-transition owner to
method-0 script copying and independent immutable combat-factor snapshots.
It checks the pending service, unacknowledged request, physical slot and side/core
addresses, installed new model and restored original entity type. It rejects
unknown flag bits and sticky child faults. It copies the owner's slot/model
inputs into the checked script controls; flag 4 clears initialization before
copying. Named variable values survive both operations.

Only successful script and factor copying writes acknowledgement 5 and invokes
the actual transition Ack. That owner advances to service 6 and clears the
acknowledgement. No other model, palette or callback service is acknowledged.
Failures leave the transition faulted. As in the ordered source operations,
a child failure can occur after an earlier child has already changed its state;
the adapter does not promise transactional rollback.

The bounded native proof passes 278 cases: all sixteen authored script/factor
descriptors, old initialized and absent instances, optional clear, slots 0, 1
and 127, all eight flag values, and 74 stale owner/child/table guards. It compares
entity rows, relation initialization, independent factor vectors and identity,
all named-variable storage and CPU context. The real owner reaches service 6
only after the actual native copiers finish. Source tables and ROM hashes are
recorded in `receipts/byor-motu-model-scripts-service-native.json`.

The request lease is installed by the isolated fixture. This does not prove
the complete weapon-frame transition, presentation binding, combat or Demo.
The foreign profile remains unregistered. No new control storage, production
assembly or bank-0 code is added. No color reduction or PCM copies are applied.
