## 1CEASY source audit

The real level declares `music data/music/1boss.bor`, background
`data/bgs/alley/back`, panels `p01` through `p05` in order `abcde`, and
`blocked 1`. It has no frontpanel, scene transition, bossmusic, wait,
hole/endhole, water/rock/mirror/direction, or script directive.

Its spawn stream contains 20 records: 19 spawns and one `group 2 2` at
level position 40. The distinct source identities are Shermie, Trash,
Yamazaki, Ralf, Yashiro, and Angel. The first Trash contains Meat; the
second uses the source `2pitem Meat` form. Yamazaki is `health 250`,
`boss 1`, and the remaining explicit Ralf is `health 70`. Several later
reinforcement records use map 1/3 values.

## Minimum runtime identity decision

Only Yamazaki was added as a new converted runtime identity. It is the
1CEASY boss and is therefore player-visible and mechanically important.
Angel and Shermie remain ordinary enemy reskins under the accepted runtime
policy; no unrelated later-campaign identities were added. Yamazaki is
after the 13 playable entries, so `PLAYABLE_ROSTER_COUNT` remains 13 and
character select behavior is unchanged. The six actor windows remain
unchanged.

The new assets are generated by `convert_bg.py`, `build_spawn_table.py`,
and `convert_character.py` from the authoritative PAK:

* `out/bg_bor_1c/` — streaming 64x28 tilemap, 1,352 unique tiles;
* `out/spawn_bor_1c/spawn_table.bin` — 20 records, 200 bytes;
* `out/yamazaki_*` and `out/yamazaki_moveset.json` — the real declared
  animations, with the known engine role subset wired by the existing
  converter.

## Acceptance boundary

The focused `game_g15_stage1_campaign.py` gate proves the three real
stage-load edges, 1C identity/width/spawn data, an opening production wave,
and the 1C handoff to the current configured TMNT development tail. That
last edge is **DEVELOPMENT TAIL HANDOFF**, not BOR stage 2: `2EASY` belongs
to Batch B.

Script VM work, actor-count growth, animation transport redesign, and pit
semantics are not Batch A blockers.
